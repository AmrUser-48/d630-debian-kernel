# Linux 6.12.95 Bookworm-backports — D630 build and validation plan

## Exact current backport target

Debian's Bookworm-backports source listing identifies `linux 6.12.95-1~bpo12+1` as the newest source version listed on 2026-10-25. Build the normal amd64 and PREEMPT_RT flavors from this same source package; do not mix source files or toolchain assumptions with Debian 13.

## Build structure

Two separate Actions workflows call the same shared build script with `BUILD_VARIANT=amd64` and `BUILD_VARIANT=amd64-rt`. Each run:
1. Configures Bookworm and Bookworm-backports apt/deb-src repositories.
2. Installs source package build dependencies selected for the backport.
3. Fetches and verifies `linux=6.12.95-1~bpo12+1` through APT/dpkg-source.
4. Downloads Debian's Intel microcode and `firmware-iwlwifi` packages, checks the microcode CPUID, and stages the two firmware files before Kconfig.
5. Generates the matching Debian baseline config with native rules, then applies the D630 overlay to just that feature set's image target.
6. Runs `olddefconfig` and checks effective CPU, firmware, compression, storage, sound, Wi-Fi and RT symbols.
7. Builds only the native runtime image target, verifies the embedded firmware bytes, and locates the exact unsigned image package.
8. Repackages that image under the installable Debian package name with version `6.12.95-1~bpo12+1+d6301`, keeping the Debian kernelrelease/module path unchanged.
9. Verifies package fields and paths, required modules, config audit and SHA256SUMS before upload and a unique pre-release.

## Config choices

The T7250 is a Core 2 Duo, so Linux 6.12 can use `CONFIG_MCORE2=y`; the CPU selection is not inferred from the remote runner. zram is built in with LZ4 as the default and all available 6.12 compressor backends enabled. ext4/NTFS3/Btrfs/FAT-family/UDF and the live-image SquashFS/OverlayFS path are built in. ISO9660 remains modular. CPU microcode and the Wi-Fi firmware are embedded into vmlinux. The GM965 GMA X3100 uses legacy i915 and does not need modern Intel display firmware; the ICH8/SigmaTel audio codec requires the HDA driver but no separate firmware.

The normal build must not enable `CONFIG_PREEMPT_RT`. The RT build explicitly enables `CONFIG_EXPERT` and `CONFIG_PREEMPT_RT` in the RT config overlay and fails if the final config does not retain it. The RT build uses Debian's native `binary-arch_amd64_rt_amd64_real_image` target.

The audit saves the complete config diff and a TSV of changed symbols, including unexpected module `m -> n` transitions for inspection. The critical D630 hardware, storage and firewall symbols are hard assertions; the audit does not blindly treat every unrelated Debian m-to-n transition as a kernel-build failure.

## Package integrity and hardware caveat

The final .deb keeps the expected ABI release and module directory and is assigned a package version newer than the corresponding official backport. It is a custom unsigned image; it must not be advertised as Debian-signed.

GitHub Actions validates sources, configuration, compilation, package metadata, firmware, and checksums. It cannot prove that the kernel boots on the real Dell Latitude D630; preserve a known-good boot entry and test the generated package on the laptop.


## Configuration correctness gate

The runner now starts from Debian's generated target config and edits it in place. The D630 settings are not merged as a second config fragment, and no Debian `rules.gen` or ABI/localversion values are changed. The CPU-family, kernel-image-compression, debug-info and zram-compressor choices are normalized before Kconfig resolution; only `MCORE2`, `KERNEL_XZ`, `DEBUG_INFO_NONE` and the LZ4 zram default may be active in those groups. The RT build also selects `PREEMPT_RT` exclusively. The runner must reject override/choice warnings, validate the Kconfig-resolved settings before compiling, and validate them again after the image target. Missing critical settings or unexplained module removals stop the build before package publication.
